The big picture

The core never draws anything and never does I/O. It hands a ViewTree down to a host and gets Msg values back. Each host has exactly one boundary where it crosses into another language: C for native, Python for web.

The pattern

The loop every host runs

This is the Elm pattern that Iced and Dioxus use in Rust. A host only has two jobs: turn raw input into a Msg, and put a ViewTree on screen. Everything inside the dashed zone is plain Mojo you can test without a window or a server.

Native host

One native frame, call by call

The operating system owns the loop, and Mojo is called. A small C file, host_main.c, receives SDL3's callbacks and passes each one to an exported Mojo function. That is the same shape as Flutter's iOS shell calling its engine, which is why this one design works on Linux, macOS and iOS. Every call across the shaded strips carries only numbers and (pointer, length) string pairs.

iOS native

iOS, the Flutter way

Flutter ships on iOS by compiling your code ahead of time into native ARM code and placing it inside a thin Xcode app that draws everything itself. mojo-ui can be packaged the same way. Every layer exists today except one: Mojo's runtime libraries have never been built for iOS. Milestone M5 is a one-day test that tells you how much of that runtime your app actually needs.

M5 resultWhat it meansNext step
GoThe iOS object file needs only system functionsLink it into the Xcode app, run "Hello, Ada!" on the simulator, then a phone
PartialIt needs a few Modular runtime piecesPort just those pieces for iOS from the open-source repo, then retry
No-go for nowThe compiler rejects the iOS target or needs most of the runtimeiOS stays on the web host; revisit after the port or an official target
Web host

One web click, request by request

On the web, the browser holds the text you type until you press Greet. Then HTMX posts the value, Python passes it straight to Mojo, and Mojo hands back finished HTML. The Python file contains routing and nothing else.

Data layout

The ViewTree in memory

The tree is not built from nested objects. It is one flat list of six nodes in depth-first order, and each node points to its first child and its next sibling by index. Walking it means following those two links. Clay, Taffy and Masonry store their trees the same way.

Where it runs, today and next

The web host is the bridge for every platform Mojo can't compile for yet. Each native target can switch over later without touching core/.
