Agent native

Every app is already
a set of agent tools.

The agent is a host, like GTK or the browser. Buttons, menus and fields become MCP tools on their own. No API to build, no screenshots to read.

# a real session: an agent opens a million rows and asks for a chart
→ choose-a-file  {"path": "orders_1m.csv"}
→ create-table
→ insert-chart
→ ask  {"text": "revenue by product, largest first, top 5"}
← Did ask.
  Now: chart0: 0.6 ms
  Now: inspector: Sum of revenue by product, largest first, top 5, as bars

No per-app work

A button's tag names its tool and its tooltip describes it. Every omxapp app is an MCP server from the first line.

Safe by construction

An agent can do nothing a person couldn't. A disabled button is no tool; a dialog's buttons exist only while it's open.

It hears what changed

Every call answers in words: the new texts, what opened or closed, which tools appeared.

The GPU, in the same language

The next step

GPU‑native
generative interfaces.

Today an AI app is two programs: an interface on one side, a model behind an HTTP API on the other, and JSON in between. Mojo is the language of both the GPU code that runs models and the GPU code that draws and computes this app. So they can be one program.

An AI app today
  1. UI in JavaScript or Swift
  2. → HTTP request, JSON
  3. model server in Python
  4. → HTTP response, JSON
  5. UI parses, re-renders

Three languages, two processes, a network hop on every answer.

Where omxapp is going
  1. your app in Mojo
  2. → the model, same process, same GPU
  3. → the data engine, same GPU
  4. → the interface, drawn on the GPU
  5.  

One language, one program, no API in between.

Not in the alpha. Today the interface, the data and the drawing share one language and one GPU; the model is the next piece.

Available today.
