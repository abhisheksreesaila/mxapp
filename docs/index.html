The problem

Four programs. One file.

The interfacewritten again for each platform.
The data workin Python, on a server.
The graphicsin a shader language.
An APIso other software, and now AI agents, can use it.

Every line between them is a rewrite, a network hop, or another team. omxapp is one program.

Mojo writes the controls, the data engine and the GPU code. The same file runs as a native app on each platform, and it's a set of agent tools the moment it runs.

Native everywhere

Real controls. Not imitations.

A button is a GTK button on Linux, an HTML button on the web, an Android view on a phone, an NSButton on a Mac. Each platform brings its own look, keyboard and screen reader. The drawn parts, like charts and the million-row grid, are one Mojo display list, replayed by each platform's GPU renderer.

Linux · runsWeb · runsAgent · runsAndroid · runsMac · buildsiPhone · builds

"runs" means a script drives it there today. Mac and iPhone build and sign; no check runs them yet.

Data on the GPU

Instant at a million rows.

The code that sums your data is plain Mojo, running on the GPU next to the code that draws it. Nothing leaves the process.

The honest edge. At 100M rows in memory, a median chart takes about 0.7 s, and today the window waits for it. Moving that work off the window is the next piece of engine work.

Agent native

Every app is already a set of agent tools.

The agent is a platform, like Linux or the web. omxapp shows it the same app as a list of MCP tools: a button's tag names its tool, its tooltip describes it, and calling the tool is tapping the button. No API to write, no screenshots to read.

Safe by construction.

An agent can't do anything a person couldn't. A disabled button isn't a tool; a dialog's buttons exist only while it's open.

It hears what changed.

Every call answers in words: the new texts, what opened or closed, which tools appeared.

Where it's going

GPU-native generative interfaces.

Today an AI app is two programs: an interface on one side, a model behind an HTTP API on the other, and JSON in between. Mojo is the language of both: the GPU code that runs models, and the GPU code that draws and computes this app. So they can be one program, where the model reads the app's data where it already sits and the interface answers in the same frame.

An AI app today

  1. Interface in JavaScript or Swift
  2. → HTTP request, JSON
  3. Model server in Python
  4. → HTTP response, JSON
  5. Three languages, two processes, a network hop per answer
